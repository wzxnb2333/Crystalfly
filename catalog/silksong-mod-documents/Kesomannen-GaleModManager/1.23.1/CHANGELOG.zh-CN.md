## 1.23.1 (2026-10-03)

### 修复

- 更新了 webkit 版本，并修改了 AppImage 构建版本，以解决 Linux 系统上出现的白色屏幕问题（感谢 [@arrowmaster](https://github.com/arrowmaster)）

## 1.23.0 (2026-10-02)

### 新增功能

- 添加复制链接上下文菜单选项，可复制模组的 Thunderstore 或 Hexium 链接
- 乌克兰语翻译（感谢 [@VoronUA1](https://github.com/VoronUA1)）
- 在模组包上传对话框中提示：若该模组包被上传为隐藏模组（感谢 [@bwoebi](https://github.com/bwoebi)）
- 可在模组详情菜单中查看模组的 Thunderstore 和 Hexium 版本（当版本可用时）
  - 点击“安装”按钮将安装当前选中来源的版本
  - 原先的行为是始终选择版本号更高的来源；现在默认选择该来源，不再强制执行
- 模组上下文菜单新增切换来源选项
- 可配置代码导出和同步配置文件时包含哪些文件
  - 当因大小限制导致配置文件导出被拒绝时，现在会弹出对话框提示，而非显示标准错误信息
- 支持 Nucleus 模组加载器（感谢 [@u0068](https://github.com/u0068)）

### 修改内容

- 下载重试现在使用范围查询来恢复上次失败的位置，而不是重新开始整个下载过程
- `Copy debug info` 现在以更易读的人类可理解格式显示模组名称，而非原始依赖字符串
- `Copy debug info` 现在按字母顺序排序模组列表
- 自定义启动参数字段现在支持带前缀的参数，类似于 Steam 的自定义参数（感谢 [@avnyu](https://github.com/avnyu)）
  - 例如现在支持像 `cmd --arg %command%` 这样的情况。此前 `cmd --arg` 会被视为一个单一可执行文件
  - **包含重大变更**：之前包含 `=`（如 `--opt=value` 或 `ENV=value`）的词始终被当作环境变量传递。此次更新后，只有符合环境变量命名规范的才会被视为环境变量（意味着 `--opt=value` 现在将作为参数传递）
- 依赖解析器现在优先选择已安装模组的来源以满足依赖关系
  - 这意味着 Thunderstore 模组的依赖项将始终从 Thunderstore 安装，反之亦然，只要该依赖字符串存在于对应平台
  - 如果依赖项已在配置文件中存在，则会直接使用，不受来源影响
- 在决定优先选择哪个来源时，现在会考虑模组的弃用状态
  - 被弃用的模组来源将始终被非弃用模组覆盖，即使非弃用版本的版本号更低或相等
- “更改版本”上下文菜单中不再显示模组当前版本
- 小幅 UI 改进

### 修复内容

- 跨平台更新未在模组卡片上显示，仅在“全部更新”对话框中显示
- 切换配置文件时同步状态未刷新
- 删除的配置文件在配置编辑器中仍保留，直到应用重启
- 同步捐赠提示每次打开对话框都会重新出现
- 配置文件编辑器在切换配置文件后有时会变得过时
- `gale://` 和 `ror2mm://` 深链接现在从指定的来源安装，而非自动确定来源
  - 这意味着 Thunderstore 和 Hexium 网站上的“使用模组管理器安装”按钮将始终从正确来源安装
- 配置文件导入时部分模组可能被错误地从不正确的来源安装
- 当检测到 NVIDIA 显卡时，Linux 上现在自动设置 `WEBKIT_DISABLE_DMABUF_RENDERER=1`，应可解决某些系统上的渲染问题
- 导出大型配置文件或代码时 UI 有时会冻结
- 俄语翻译大幅优化

## 1.18.0 (2026-07-13)

### 新增

- 支持空洞骑士的 [Hexium](https://hexium.gg/) 模组平台（感谢 [@bwoebi](https://github.com/bwoebi)）
  - 默认情况下，Hexium 模组会与 Thunderstore 模组一同获取。您可以在 Valheim 特定设置中选择不使用任一平台
  - 模组列表显示来自两个平台的模组。如果某模组同时存在于两个平台，且版本相同，则优先采用 Thunderstore 的版本
  - 若所有模组及其版本均发布在 Thunderstore 上，则配置文件和模组包导出将发送至 Thunderstore；否则将上传至 Hexium，并仅在 Gale 中可用，不会出现在官方 Thunderstore 模组管理器中

### 修改

- 移除模组列表中的标签
- 其他细微的 UI 优化
- 对不支持模组包的游戏/社区，已禁用模组包导出页面
  - 包括 WEBFISHING (GDWeave) 和 Northstar
- 模组包导出页面现在会列出可通过模组包正确导入的配置文件
  - 现在包含所有位于配置目录中的文件，例如 `BepInEx/config`（详见下方完整列表），而不再仅限于特定扩展名的文件
  - 排除了一些之前错误包含的文件，如 `BepInEx/plugins/<AUTHOR-NAME>` 中的文件

### 修复

- Linux 系统中 Gale 被注册为所有 zip 文件的处理器（感谢 [@Damglador](https://github.com/Damglador)）
- 改进了简体中文翻译（感谢 [@lostone-zc](https://github.com/lostone-zc)）
- 某些字段更改后模组包导出页面能够正确刷新
- 配置目录中多余的文件不再被包含在配置文件导出中
  - 现在与 r2modman 的行为一致，适用于 BepInEx，并额外支持其他模组加载器
  - 被识别的配置目录如下：
    - `BepInEx/config`
    - `Renderer/BepInEx/config`

- 改进了瑞典语本地化
- 优化了数据库被较新版本 Gale 修改时的错误提示
- Hades II 模组加载器文件现在被放置在游戏根目录，而非嵌套的 `Ship` 目录中
- 原本未将 shimloader 代理 DLL `dwmapi.dll` 添加到 `WINEDLLOVERRIDES` 中，导致 Windows UE 游戏在 Linux 上以未模组化方式启动
