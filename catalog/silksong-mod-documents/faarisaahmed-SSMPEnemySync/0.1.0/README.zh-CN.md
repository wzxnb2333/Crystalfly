# SSMPEnemySync

一个为 [SSMP](https://github.com/Extremelyd1/SSMP)（空洞骑士：丝之歌 多人模式）设计的插件，  
使敌人在双方玩家之间**共享**。

一个敌人。一个生命值池。任一玩家攻击它，两次攻击都会作用于同一个生命值条，  
当敌人死亡时，对双方玩家来说都算死亡。首领怪物也包含在内。

没有这个插件的情况下，每位玩家都将面对自己私有的敌方副本，仅有一人能真正击杀敌人。

## 要求

- **[BepInEx for Silksong](https://thunderstore.io/c/hollow-knight-silksong/p/BepInEx/BepInExPack_Silksong/)**
- **[SSMP](https://github.com/Extremelyd1/SSMP) 0.3.1.0**

> **两名玩家都需要安装此插件，并且版本必须相同。** SSMP 会根据名称和版本匹配网络插件，版本不一致将完全无法连接。

## 安装

首先安装 BepInEx 和 SSMP，并确认多人模式本身可以正常运行。

然后将 `SSMPEnemySync.dll` 放入 **已包含 `SSMP.dll` 的文件夹中**：

```
Hollow Knight Silksong/
└── BepInEx/plugins/
    └── SSMP/                 ← whatever folder your SSMP.dll lives in
        ├── SSMP.dll
        └── SSMPEnemySync.dll ← here
```

**必须是这个确切的文件夹。** SSMP 的插件加载器只会扫描其自身程序集所在的目录。如果放在其他位置，插件将被静默忽略——不会有任何错误提示，它完全不会生效。

如果你通过模组管理器进行安装，请之后确认 DLL 文件是否位于 `SSMP.dll` 旁边，而不是单独在一个文件夹内。

启动游戏。BepInEx 日志中应显示 `[EnemySync] Initialised.`

## 它实际上做了什么

SSMP 已经自带了一个完整的主机/客户端实体系统，能够同步敌人位置、动画、FSM 状态以及死亡状态。但在丝之歌中，有三个问题导致该系统无法正常工作，本插件从外部提供了全部解决方案：

1. **该功能被关闭了**。启动实体管理器的调用在 `ClientManager` 中被注释掉了。
2. **完整的同步默认是关闭的**，并且在主机和客户端两端都对每个实体数据包处理进行限制。原本用于开启此功能的菜单选项也被注释掉了。
3. **实体注册表属于空洞骑士 1**，因此丝之歌中的敌人无法被识别为实体。

此外，该插件还增加了健康值同步功能，而实体系统本身从未具备这一特性。

### 健康值如何保持准确

**场景主机**是权威方。客户端检测到伤害命中后会上报，然后在本地撤销该操作，以避免重复计数；主机应用伤害并广播结果。

死亡事件通过游戏自身内置的死亡流程处理，而非简单地将健康值设为零，因此正确的特效得以触发，战斗脚本逻辑也得到尊重，SSMP 自身的死亡同步机制也能正确识别到这一状态。

健康值会定期重新广播，同时在发生变化时也会广播，这样即使出现数据延迟，玩家的血条也能自动修复，而不会导致某位玩家看到过期的数值。

## 卸载

删除 `SSMPEnemySync.dll`。SSMP 将恢复到其之前的行为——该插件不会修改任何文件。

## 限制

- **依赖 SSMP 0.3.1.0。** 它通过反射访问 SSMP 的内部机制，因为其实体系统完全是 `internal`，而附加组件 API 故意不暴露任何关于实体的信息。在不同的 SSMP 构建版本中，它会在启动时自动禁用自身，并记录原因，而不是出现异常行为。
- **敌对单位注册表仅涵盖早期游戏的敌人。** 对于它无法识别的敌人，不会被当作实体处理，因此这些敌人将保持未同步状态。
