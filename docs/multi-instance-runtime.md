# 多实例运行与存档隔离

Crystalfly 可以同时运行 HK 和丝之歌，也可以运行同一游戏的多个不同实例。同一个实例不能重复启动；需要第二份独立进度时，先创建或克隆实例。

## 存档位置

游戏直接读写原有实例目录中的 `instances/<id>/local-low`。HK 使用该目录下的槽位文件，丝之歌保留其 `default` 或 Steam 账号子目录结构。启动和退出均不再交换系统共用 LocalLow 目录，也不在退出后复制回存档。

旧版本未完成的 LocalLow 事务仍按原有恢复机制检查。尚未安全恢复时不会启动新会话；原有存档、快照格式和路径保持兼容。

## Windows 启动方式

- 在游戏入口执行前，为 Unity 的静态和动态 shell-folder 查询设置进程内重定向；不改写磁盘上的游戏或加载器二进制文件。
- 独立用户目录映射位于应用数据的 `runtime-profiles`，以实际存档路径的散列区分。受控目录连接指向该实例的存档；不放入游戏目录或实例备份树。
- 每个存档目录持有独立的命名锁，句柄由游戏进程继承。启动器退出或崩溃不释放仍在运行游戏的锁，也不终止已启动的游戏。
- 建立隔离失败会结束尚未正常启动的子进程，不回退到共用存档。现有实现要求 Windows x64 游戏及受支持的 Unity 路径查询方式。

运行游戏时允许导航、选择实例及切换游戏。修改游戏文件、恢复存档等操作仍保留进程检查；当前部分写入保护按整个游戏生效，范围比单实例更保守。

## 验证范围

专项覆盖路径查询、动态函数查找、目录连接目标校验、存档树重解析点拦截、不支持的程序启动失败、双实例状态、重复启动、关闭启动器及旧事务恢复。

本地验证使用 HK 1.5.78.11833 和丝之歌 1.0.30000，包含现有加载器和模组，实际同时启动两份 HK 与两份丝之歌。通过游戏生成存档并检查目标目录、其他实例及原共用目录；验证启动器退出后保存和锁仍有效。

这不是所有历史游戏版本、任意模组自定义路径或比赛规则的兼容性认证。游戏本身在写入瞬间崩溃、断电或磁盘故障仍可能损坏本次写入；隔离消除的是实例之间争用与退出回写造成的风险。
