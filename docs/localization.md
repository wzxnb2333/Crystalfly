# 界面本地化约定

## 范围

应用自有的用户可见文案统一使用 `LocalizationViewModel` 的 English 与 Simplified Chinese 双字典。包括页面标题、按钮、工具提示、空状态、动态状态、错误提示和 `AutomationProperties.Name`。

新增界面文案必须同时添加英文键和值、简体中文键和值，并使用 `Loc[key]` 绑定或 ViewModel 的本地化计算属性。带参数的文案必须在两种语言中保持相同的格式占位符。

## 与 Mod 翻译目录的边界

`catalog/mod-translations.zh-CN.v1.json` 只负责 Mod 官方元数据的中文翻译，例如 Mod 名称、说明和标签。它不替代 UI 字典，也不应把界面按钮、错误信息或状态文本写入 Mod catalog。

Mod 名称、作者名、游戏官方元数据和远程服务返回的原始内容保留其来源语言；应用只本地化包围这些内容的 UI 文案。

## 允许保留原文

以下内容可以保留原文，不作为 UI 漏译：

- Crystalfly、Steam、Avalonia、Ursa 等产品或技术名称；
- Mod 名称、作者名、游戏和 Mod 官方元数据；
- URL、仓库地址、文件路径、版本号、AppID、DepotID 和协议字段；
- 用户输入、远程服务返回的错误详情、日志和调试输出；
- 开源许可证名称及其他法律或协议标识。

如果这些内容出现在按钮、工具提示或无障碍名称中，外围动作描述仍应通过本地化资源提供。

## 验证

本地化测试检查中英文键集合、空值和格式占位符的一致性。中文截图用于检查布局和文本溢出，但不是唯一的本地化验证；英文界面也必须保留可用并通过基本回归测试。
