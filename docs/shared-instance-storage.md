# 共享资源实例

实例列表的悬浮操作提供两个入口：“创建共享实例”（Layers）和“创建完整副本”（Copy）。
共享实例在本地 NTFS 磁盘上复用经过校验的大型 Unity 资源；完整副本复制所有游戏文件。
已有普通实例和 HK 正式速通实例可在实例卡片的“更多 → 节省空间”转换共享。
需要使用外部工具直接修改游戏资源时，先在同一菜单选择“转为独立副本”。
切换存储方式需要关闭目标游戏并完成该实例的下载与事务恢复。

实例页采用连续关系线表示克隆来源，实例始终展开，卡片保持对齐，不使用阶梯缩进。
没有关系线的独立实例显示定位圆点；搜索子实例时保留对应来源关系。
悬浮工具栏保留共享克隆、完整克隆、管理和更多；收藏、存储转换及删除位于更多菜单。

## 数据与隔离

- 实例页按版本分组，新克隆通过 `ParentInstanceId` 保存来源关系，两种克隆都显示在来源实例下面。
  `ParentInstanceName` 保留创建时的来源名；父实例删除或不在当前分组时，子实例仍可单独管理。
  旧实例没有历史来源记录，只按版本展示，不按名字或创建时间虚构父子关系。
- 右上角“实际占用”统计当前目录、当前游戏的已登记实例文件、共享基础库和实例存档/快照。
  使用 Windows 文件标识去重和 `FILE_STANDARD_INFO.AllocationSize` 统计物理分配空间；
  排除 MFT 等文件系统元数据、外部目录及未登记实例。游戏文件重复引用部分计入“共享节省”，
  基础库自身的链接不虚增节省量。统计在后台进行，进入页面、实例集合更新或手动刷新时重算。
  遇到无法读取的文件会显示“已统计 ≥”和部分统计提示，不将缺失部分当成零。

- 资源按游戏身份及 SHA-256 存放于版本根目录的 `.crystalfly/shared-content-v1`。
  内容相同的文件通过 NTFS 硬链接共享磁盘数据；不同内容不会因为版本号或文件名相同而合并。
- 只处理游戏数据目录内明确列出的资源格式，且文件至少 1 MiB。
  程序集、加载器、模组、配置、日志、存档与快照仍独立。
- 共享文件使用 ACL 禁止直接改写，仍允许删除单个链接。
  普通硬链接没有自动写时复制：应用的安装事务采用删除/替换文件路径形成独立文件；
  不使用应用的外部修改工具，应先独立化整个实例。
- 原来的实例存档和进程隔离机制不变；多个实例可以同时读取同一资源并使用各自存档。
- `InstanceRecord.UsesSharedContent` 是兼容旧数据的可选字段，默认 `false`。
  升级安装不会批量迁移已有游戏；显式优化或克隆时才转换。

## 失败与恢复

- 转换先保存共享状态，再逐文件校验和原子替换。取消或失败可能留下部分共享，内容不变；
  可以重新执行优化，或转为独立副本。不会删除用户存档。
- 哈希计算期间持有禁止写入的源文件句柄，替换前核对文件身份。
  使用 NTFS 原子替换在保留读句柄的情况下完成目录项切换。
- 基础库有跨进程文件锁；临时工作文件在下次进入时清理。
  原始文件仍存在时才发布资源，写入与独立化都进行哈希校验。
- 删除实例只删除它自己的文件链接。基础库仅在链接数为 1（只剩基础库本身）时回收资源，
  优化、独立化、实例删除及删除恢复均会触发检查。
- 基础库路径不参与实例扫描，所有路径继续拒绝重解析点。

## 兼容范围

- Windows、本地 NTFS；其他文件系统的克隆回退为原来的完整复制。
- Steam 原始目录不转换共享；应先迁移到独立版本目录。
- 正式 HK 速通环境创建时优先共享游戏资源；RuntimePatches 程序集、配置与存档独立。
  不支持共享的位置自动使用完整复制。既有环境可主动执行“节省空间”，不会自动转换。
  校验器允许共享资源，仍检查专用实例、模板、文件哈希、事务及存档状态。
- 不应使用旧版启动器修改共享实例，也不应手工删除保护权限。
  降级或交给需要直接写资源的外部工具之前，先转为独立副本。
- Windows 资源管理器可能把硬链接的逻辑文件大小重复计入目录大小；
  应结合卷剩余空间或文件标识、链接数判断实际占用。
